# Бесплатный запуск @avangardstories_bot без банковской карты

Выбранная схема: **GitHub → Render Free + Supabase Free**.

GitHub хранит код. Render запускает бота по входящим сообщениям Telegram. Supabase хранит очередь команд, состояние чатов и оригинальные файлы. На локальный диск Render как на постоянное хранилище бот не полагается.

## Сначала — аккаунты

1. Войдите или зарегистрируйтесь на [GitHub](https://github.com/).
2. Зарегистрируйтесь в [Render](https://dashboard.render.com/) через GitHub, выберите бесплатный Hobby workspace и Free web service.
3. Зарегистрируйтесь в [Supabase](https://supabase.com/) через GitHub, создайте организацию Free и проект. Название: например `avangard-stories`. Пароль базы придумайте и сохраните; он не передаётся боту в этой схеме. Запишите регион проекта.

Карту и платные тарифы для этой схемы не выбираем. При требовании конкретному аккаунту платного плана остановиться и проверить условия, а не вводить карту или включать оплату.

## Подготовить хранилище

В Supabase откройте SQL Editor, создайте запрос и выполните содержимое `supabase.sql` из пакета бота. Он создаёт:

- приватную таблицу состояния и очередь;
- функции для последовательной обработки и сохранения команд;
- закрытый bucket `stories-originals` для фотографий, логотипов и шрифтов.

В настройках проекта найдите Project URL и **service_role key**. Это серверный секрет, не publishable/anon key. Он вводится только в защищённых переменных Render. Не публиковать в GitHub или чате.

## Загрузить код в GitHub

Создайте **приватный** репозиторий, например `avangard-stories-bot`. Загрузите содержимое папки бота в корень репозитория: рядом должны лежать `render.yaml`, `Dockerfile.render`, `requirements.lock`, `stories_bot/`, `assets/`.

Не загружать `.env`, `.venv`, `.tmp`, `data`, `demo-output`, `__pycache__`. Готовый архив `avgst-stories-bot-free.zip` уже исключает их.

## Подключить Render

В Render: New → Blueprint → выбрать приватный репозиторий. Файл `render.yaml` задаёт бесплатный веб-сервис, а не платный Background Worker.

Заполните секретные переменные:

| Переменная | Откуда |
|---|---|
| TELEGRAM_BOT_TOKEN | Токен @avangardstories_bot из BotFather |
| SUPABASE_URL | Project URL из Supabase |
| SUPABASE_SERVICE_ROLE_KEY | service_role key из Supabase |
| OPENAI_API_KEY | Отдельный ключ текстовой модели; можно добавить позднее, до этого тексты не работают |

`WEBHOOK_SECRET` генерируется Render автоматически. `DATA_DIR`, `BOT_USERNAME` и режим запуска уже прописаны. Домен покупать не нужно — используется адрес `onrender.com`. При запуске бот подключает этот адрес к Telegram, старую очередь сообщений не очищает.

Сервис получает сообщения через защищённый webhook и отвечает Telegram только после записи команды во внешнюю очередь. В один момент команды выполняет один обработчик; блокировка и её срок хранятся в Supabase. Это рассчитано на небольшую нагрузку одного бота.

## Назначить владельца

После первого успешного запуска отправьте `/id` боту в личном чате. Полученное число добавьте в `OWNER_TELEGRAM_ID` в Render Environment и перезапустите сервис. До этого платные команды отключены.

Добавьте бота в группу. Для сообщений обычным текстом отключите Group Privacy через `/setprivacy` в BotFather и заново добавьте бота либо сделайте его администратором. Владелец отправляет `/enable` в группе.

Проверка: `текст: 6 сторис про Сканди 78` → `редакт: …` → `пришли картинками` → ответ на изображение `правка: …` → `исходники`.

## Ограничения бесплатного режима

- Render Free засыпает после 15 минут без входящих запросов. Пробуждение может занять около минуты; первая команда после простоя может прийти с задержкой. Искусственные пинги для обхода сна не используются.
- Supabase Free может приостановить проект после недели низкой активности. Возобновление делается в панели Supabase; это не гарантированная работа 24/7.
- Лимиты Supabase Free на момент проверки: база 500 МБ, файлы 1 ГБ, исходящий трафик 5 ГБ. Не храните бесконечно все проекты и изображения. Render также ограничивает часы, трафик и сборки; бесплатность действует в пределах этих квот.
- В этом режиме история SQLite сохраняется в приватной базе Supabase как согласованный снимок после команды. Файлы хранятся отдельно. При каждой обработке снимок восстанавливается, поэтому схема предназначена для небольшого количества серий, а не большого публичного сервиса. Ограничение снимка — 20 МБ.
- При обрыве до сохранения результата команда повторяется. Повторная отправка сообщения в Telegram или повторный вызов модели возможны; строго однократная внешняя отправка не гарантируется.
- Бесплатный хостинг **не означает бесплатную текстовую модель**. Текущая версия требует отдельного API-подключения. Альтернативная бесплатная модель потребует отдельной проверки и адаптации.

## Статус проверки

Локальные проверки выполнялись с подменённым Supabase и Telegram. Проверено восстановление снимка на новом локальном пути, контрольные суммы исходников, отказ неавторизованным webhook-запросам и ответ 503 при недоступном хранилище. SQL-функции на настоящем Supabase и размещение на Render ещё не проверены: аккаунты и ключи не подключены. Docker локально отсутствует, контейнер здесь не собирался.
